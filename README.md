# XU-AI-Assistant

> 墟 · AI Assistant：让 XU 知识库和你已经登录的 AI 账号同时留在桌面上。

当前版本：`0.1.5`

[XU 知识库](https://xu.lucifer-cgl.workers.dev/) 是一个无需后端与数据库的静态课程知识平台。国内访问入口为 <https://lucifer.gicp.fun/>。XU-AI-Assistant 是它的可选浏览器扩展：读取访客当前正在浏览的 XU 内容，整理成可控的学习提示词，再打开访客自己选择并已经登录的 AI 官网。

它不是新的 AI 品牌，不代理模型，不提供共享账号，也不要求 API Key。

## 现在能做什么

- 在 XU 页面右下角显示“墟”入口，并打开浏览器侧边栏。
- “墟”入口可拖动到网页任意可见位置，并按窗口比例记住位置。
- 按“选中内容 / 当前章节 / 整篇文章”三种范围读取正文。
- 允许用户先预览将要交给 AI 的文字，再决定是否继续。
- 打开助手时默认收起本文目录，但保留分栏图标供用户随时重新展开。
- 为文章内容和用户提问分别提供复制按钮。
- 支持 ChatGPT、Gemini、DeepSeek、通义千问和豆包。
- 将组合提示词复制到剪贴板，并用独立窗口打开 AI 官网。
- 宽屏设备按当前显示器可用区域自动排列为 XU 左侧约 70%、AI 右侧约 30%；关闭 AI 后恢复 XU 原窗口状态。
- 根据浏览器语言和时区给出大陆/海外网络提示，但不采集精确位置。
- 点击“检查更新”对比仓库中的最新版本。
- 不保存账号、密码、文章内容或对话记录。

## 为什么采用浏览器扩展

AI 官网通常禁止被第三方网页直接嵌入，普通 XU 页面也不能跨域读取这些网站的登录状态。扩展只承担三件事：从 XU 读取用户指定的上下文、整理并复制提示词、打开官方 AI 页面。

登录、回答和历史记录仍留在 AI 官方网站中。这样既能让 XU 和 AI 同时存在，又不需要为 XU 增加服务器、数据库、API Key 或持续的模型费用。

浏览器扩展不能把第三方官网窗口设为系统级“始终置顶”，也不会通过高权限脚本代替用户在第三方页面发送问题、读取回答。当前方案采用无重叠并排窗口和用户确认后粘贴发送，优先保证稳定、透明与账号安全。

## 安装

目前采用免商店的“加载已解压扩展”方式，适用于 Chrome 与 Edge：

1. 下载仓库 ZIP，并解压到一个长期保留的文件夹。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展”，选择包含 `manifest.json` 的目录。
5. 打开 [XU](https://xu.lucifer-cgl.workers.dev/) 或 [国内入口](https://lucifer.gicp.fun/) 的任意文章，点击右下角“墟”。

完整说明见 [安装与使用](docs/安装与使用.md)。

## 更新

侧边栏底部的“检查更新”会比较本地版本与仓库中的 `version.json`。由于这是未上架商店的本地扩展，浏览器不会允许网页静默替换扩展代码；发现新版本后需要重新下载并解压覆盖原目录，再到扩展管理页点击“重新加载”。

这个限制是浏览器的安全边界，不应绕过。

## 隐私与安全边界

- 扩展只在 `xu.lucifer-cgl.workers.dev` 和 `lucifer.gicp.fun` 注入入口和读取正文。
- 文章内容只在用户点击某个 AI 服务时写入本机剪贴板。
- 扩展不会读取 AI 官网密码、Cookie 或对话历史。
- AI 官网的可用性、账号政策和内容处理规则由对应服务商决定。
- 时区与浏览器语言只用于本地提示，不会上传。
- 显示器可用区域只用于本地排列窗口，不会上传。

详见 [隐私说明](PRIVACY.md)。

## 项目结构

```text
XU-AI-Assistant/
├─ manifest.json        # Manifest V3 权限与入口
├─ background.js        # 侧边栏、AI 独立窗口与窗口恢复
├─ content.js           # XU 正文读取与章节识别
├─ content.css          # XU 页面上的“墟”入口
├─ panel/               # 助手侧边栏界面
├─ docs/                # 安装与使用说明
├─ version.json         # 手动更新检查的版本源
└─ .github/workflows/   # 标签发布时打包 ZIP
```

## 开发原则

1. 无后端、无数据库、无中转服务器。
2. 默认不保存内容；发送前必须让用户看得见、选得清。
3. 不伪装成任何模型厂商，也不绕过厂商登录、网络和付费限制。
4. 不依赖大型框架，保持仓库和扩展体积轻量。
5. 自动化能力宁可少，也不通过脆弱的网页脚本代替用户点击“发送”。
